# Autonomous Data Warehouse Engineering Platform (ADEP)

A collaborative AI Data Engineering Crew built using **CrewAI Flows** to profile, design, validate, and transform raw department datasets into an analytics-ready dimensional warehouse.

---

## Architecture Blueprint

```
                     Raw Datasets (CSV, Excel, JSON)
                                    ↓
                         [Data Profiling Stage]
                Profiles structural metadata dynamically
                                    ↓
                        [Data Quality Assessment]
             Audits data quality & calculates Quality Score
                                    ↓
                    [Human-in-the-Loop Threshold Gate]
             Operator approval required if Quality Score < 60
                                    ↓
                          [Schema Design Stage]
                Logical Star Schema modeling (Fact_/Dim_)
                                    ↓
                     [Transformation & Loading Loop]
         Schema Plan JSON → Per-Table Build (duckdb table-by-table)
         Verification & Retry loop (up to 3 automatic SQL fixes)
                                    ↓
                         [Warehouse Validation]
          Validation Engineer runs assertion tests & checks retention
                                    ↓
                         [Business Analytics]
             Extracts KPIs, funnels, metrics from tables
                                    ↓
                       [Final Executive Reporting]
              Summarizes results & logs token usage profiles
```

---

## Crew Structure & Specialized Agents

The crew consists of **6 specialized agents** that operate alongside deterministic guardrail modules (`EntityClassifier` and `WarehouseMetrics`) which handle profiling and validation natively in Python to prevent hallucination. The autonomous agents are:

1. **Chief Data Architect & Manager (`lead_architect`)**
   - **Role:** Coordinates the crew, delegates tasks, reviews technical outputs, and compiles the final executive recommendations blueprint.
   - **Tools:** `SearchPastExecutionsTool`.

2. **Lead Data Quality Assurance Engineer (`quality_engineer`)**
   - **Role:** Rigorously audits source datasets for anomalies, format issues, and domain rule violations, outputting a mathematically calculated Quality Score (0–100).
   - **Tools:** `ProfileCSVFileTool`, `RunDuckDBQueryTool`.

3. **Data Feasibility Analyst (`intent_validator`)**
   - **Role:** Evaluates raw data profiles to verify if the source datasets can answer the user's business questions before any schema is built.
   - **Tools:** None (reasons over provided context).

4. **Principal Data Warehouse Architect (`warehouse_architect`)**
   - **Role:** Maps raw files to e-commerce concepts, designs the Kimball Star Schema, plans table loading order, and generates/fixes transformation SQL.
   - **Tools:** `RunDuckDBQueryTool`, `SavePastExecutionTool`, `SearchPastExecutionsTool`.

5. **Senior Analytics Engineer (`analytics_engineer`)**
   - **Role:** Searches past memory query patterns, executes advanced analytics SQL (window functions, cohort analysis, logistics, conversion funnels), and writes interpretive business insights.
   - **Tools:** `RunDuckDBQueryTool`, `SearchPastExecutionsTool`, `SavePastExecutionTool`.

6. **Data Analyst (`data_chat_analyst`)**
   - **Role:** Answers specific user follow-up questions about the warehouse database by writing and executing precise SQL queries.
   - **Tools:** `RunDuckDBQueryTool`.

## Pipeline Flow Orchestration (`flow.py`)

`DataEngineeringFlow` manages shared state via `DataEngineeringState` (Pydantic Model) and coordinates pipeline execution steps:

### 1. `profile_datasets`
- Locates files (`.csv`, `.xlsx`, `.xls`, `.json`) in the active directory.
- Profiles columns, sample records, and checks for mid-file schema shifts.
- Executes `EntityClassifier` to deterministically categorize files into ground-truth entities (e.g., `orders`, `products`, `payments`, etc.) to prevent LLM hallucination.
- Saves the output profile as `profiling_report.json`.

### 2. `validate_intent`
- The Data Feasibility Analyst evaluates the profiling report against the user's intended business questions.
- If the dataset lacks required columns or entities to answer the questions, the pipeline aborts early to prevent hallucinated answers.

### 3. `assess_quality`
- Analyzes column profiles, duplicates, and missing values.
- Documents findings and writes `quality_report.md` with an audit score.

### 4. `check_quality_threshold` (HITL Gate)
- Routing step that evaluates the quality score.
- **Under 60:** Triggers approval prompt. 
  - *CLI Mode:* Pauses for operator input via `stdin`.
  - *Web Mode:* Blocks a background daemon thread callback via `threading.Event` until approved/denied via the API.
  - *Non-TTY environments:* Auto-approves to prevent build blocking.

### 5. `design_schema`
- Standardizes tables according to the Kimball Star Schema design pattern.
- Formulates primary and foreign keys and names tables with `Fact_` or `Dim_` prefixes.
- Saves design to `schema_design.md`.

### 6. `plan_transformations` (Verification & Retry Loop)
- **Schema Planning:** The Warehouse Architect designs a structured execution plan JSON. As a guardrail, the `SchemaPlanner` automatically injects any source datasets with $\ge$ 5,000 rows that were omitted, ensuring zero data loss.
- **Per-Table Build Loop (`TableBuilder`):**
  - Iterates through the table plan in order.
  - Generates specific DDL and DML scripts per table (`create_generate_table_sql_task`).
  - Executes scripts inside DuckDB and checks constraints (e.g., Fact table row counts must be $>0$).
  - If a script execution fails or empty tables are detected, `TableBuilder` triggers a retry loop (up to **3 retries per table**). It enriches raw DuckDB error messages (diagnosing UNION mismatch counts, missing columns, table references) and prompts the architect to correct it via `create_fix_table_sql_task`.
- **Data Retention Check:** Validates that combined fact table row counts match expected source counts ($\ge 70\%$).
- **Warehouse Validation:** Deterministic `WarehouseMetrics` engine executes assertions against database tables, generating `validation_report.md`.
- **Verified Metrics:** Deterministically computes warehouse statistics directly from DuckDB (`compute_verified_metrics`) to pass to the insights agent.

### 7. `run_analytics`
- Analytics Engineer runs analytics queries using CTEs, window functions, and cohorts on the live data warehouse, outputting `kpi_report.md`.

### 8. `verify_answers`
- Independently recomputes agreed metric definitions and cross-checks them against the analytics report.
- If the report deviates from defined logic, feeds divergence back to the analytics agent to recompute the metric exactly (up to 1 correction round).

### 9. `compile_final_report`
- Combines design reports, data quality metrics, validation status, and queries into a unified `executive_summary.md`.
- Computes and exports agent token usage profiles to `token_usage_report.json` and `token_usage_report.md`.


## Running Instructions & Commands

### Setup Environments & Dependencies
Ensure Python 3.12 is active and install packages:
```bash
python -m venv venv
source venv/bin/activate
pip install crewai polars duckdb chromadb fastapi uvicorn python-dotenv calamine openpyxl charset-normalizer
```

### CLI Mode execution
Runs the entire crew flow from terminal start-to-finish:
```bash
python main.py
```

### Web Dashboard execution
Serves a modern single-page dashboard for interactive execution, live log tracking, file uploading, and report viewing:
```bash
uvicorn app.server:app --port 8000 --reload
```
Open a browser and navigate to `http://localhost:8000`.

### Switching Datasets
Use the utility script to backup the active dataset and load a target dataset (`fuzzy`, `olist`, `mock`, `amazon`):
```bash
python switch_dataset.py [fuzzy|olist|mock|amazon]
# Defaults to mock dataset if no arguments are provided.
```

### Running Tests
Execute unit tests using pytest:
```bash
python -m pytest tests/
```

## Core Guardrails & Advanced Features

* **Memory Store (ChromaDB):** Saves error strategies and schema decisions inside `.chroma/` using `SavePastExecutionTool` and `SearchPastExecutionsTool`. Prevents cross-dataset contamination by applying entity-overlap thresholds and semantic cosine distance filtering.
* **Deterministic Classifications:** Integrates `EntityClassifier` (heuristic scoring) before LLM interactions to define ground-truth tables, avoiding naming confusion.
* **Date Parsing Guard:** Instructs agents to use explicit `try_strptime` patterns rather than loose castings, preventing invalid timestamp constraints.
* **Automatic Column Counting:** Dynamically counts columns during UNION failures, enriching the LLM feedback context with direct instructions to balance the branch structure with NULL placeholders.
* **Token Optimization & Tracking:** Custom telemetry tracking hooks on Crew execution gather detailed token usage profiles per agent role.
* **LangSmith Observability:** Integrated native LangChain/LangSmith tracing capabilities to automatically monitor agent thoughts, task completions, tool parameters, latency, and cumulative API token costs in real-time under a visual execution tree.
